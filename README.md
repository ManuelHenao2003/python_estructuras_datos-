# python_estructuras_datos-

En todo este recorrido de aprendizaje con Python siento que avancé bastante en la forma en la que entiendo y escribo código. Al inicio veía las estructuras de datos como algo separado y un poco mecánico, pero ahora entiendo que cada una tiene un propósito específico y que lo importante no es solo saberlas usar, sino saber cuándo y por qué utilizarlas.
Con las listas aprendí a organizar información de manera flexible, a recorrerla y modificarla, y a usar técnicas como slicing, métodos de modificación y comprensiones. Esto me ayudó a escribir código más corto y eficiente, pero también a entender que las listas son una de las bases más importantes para trabajar datos en Python.
Con los diccionarios entendí cómo representar información más real, usando claves y valores. Aprendí a hacer operaciones más avanzadas como filtrado, transformación, unión de datos y cálculos como totales y porcentajes. Esto me permitió ver Python como una herramienta muy útil para análisis de datos y no solo para ejercicios básicos.
Las tuplas me enseñaron la importancia de la inmutabilidad, es decir, de proteger datos que no deben cambiar. También aprendí a desempaquetarlas y a ver cómo funcionan en situaciones donde se necesita seguridad o estructura fija. Esto me ayudó a entender mejor cómo Python maneja la memoria y la referencia de datos.
Con los sets entendí cómo trabajar con datos únicos y cómo hacer comparaciones entre conjuntos de forma rápida y eficiente. Operaciones como unión, intersección y diferencia me ayudaron a pensar en los datos desde otra perspectiva, más lógica y matemática, lo cual facilita mucho resolver problemas reales.
Además, con las list comprehensions, dictionary comprehensions y set comprehensions aprendí a escribir código más limpio y expresivo. También entendí los generadores, que me enseñaron a optimizar memoria y a pensar en eficiencia cuando se manejan grandes cantidades de datos.
Finalmente, todo esto me hizo comprender algo muy importante: en programación no existe una única forma correcta de hacer las cosas. Siempre hay varias soluciones, pero lo clave es elegir la más adecuada según el contexto. Aprendí a pensar más como programador, a analizar problemas antes de resolverlos y a escribir código más claro, eficiente y organizado.
